# harness-backlog

세션이 끝나면 **다른 모델**이 하네스(AGENTS.md · 스킬 · 문서 · 스크립트 · 권한 설정)의 빈틈을 backlog에 제안한다. **반영은 사람이 한다.**

## 왜 만들었나

에이전트와 일하면 하네스의 빈틈이 계속 드러난다. 알려준 정책, 바로잡은 실수, 한참 헤맨 탐색. 그런데 세션이 끝나면 사라진다. 그렇다고 에이전트가 하네스를 직접 고치게 하면 **오답이 정답 행세를 한다.** 에이전트는 자기 답이 틀린 줄 모르기 때문이다.

## 무엇을 해주나

```
세션 종료 ─ SessionEnd 훅 ─ 다른 모델이 검토 ─┐
"세션 검토해줘" ──────────────────────────┤
주간 launchd ─ 놓친 세션 검토 + 여러 세션 종합 ─┤
                                            ▼
                     .local/harness-backlog/*.md   (pending — 아직 하네스가 아니다)
                                            ▼
"backlog 보자" → 항목별 반영 / 기각 / 보류
   반영 → target 수정 → _resolved/ (applied + 왜 + 바꾼 곳)
   기각 → _resolved/ (rejected + 왜)   ← 같은 제안이 다시 나오지 않게 하는 근거
```

- 항목마다 내용 · 근거(누가 무엇으로 확인했나, 추론이면 표시) · 기존 하네스와의 관계를 적는다.
- 주간 검토가 여러 세션에 걸친 반복 · 재발 · 에이전트 간 차이를 찾는다.
- 기각 이유가 쌓이면 검토 지침을 고칠 근거가 된다.

## 어떻게 쓰나

묶음에 없다. 프로젝트에 훅과 설정을 놓는 설치형이라 `scripts/setup.py`로 계획을 보고 승인한 단위만 적용한다. 세션 기록이 상대 벤더의 모델로 보내진다는 점을 먼저 알린다.

> backlog 보자
> 세션 검토해줘
> 이거 반영해 / 기각해

절차는 [SKILL.md](SKILL.md)에 있다.

## 설계에서 정한 것

- **AI는 제안하고 반영은 사람이.** 이 스킬의 유일한 원칙이다. 에이전트는 자기 하네스를 고치지 않는다.
- **교차 검토.** Claude 세션은 Codex가, Codex 세션은 Claude가 본다. 같은 모델이 자기 세션을 보면 자기 실수를 못 본다.
- **backlog는 git 밖, 메인 트리에.** 코드와 함께 브랜치를 따라가면 안 되는 데이터라서 `.local/`에 두고 `.gitignore`에 넣는다. 어느 worktree에서 일해도 한 곳에 모인다.
- **vendor 이름 규칙의 예외.** 훅 · 설정 파일 경로가 벤더마다 달라 이름을 써야 한다 → [원칙](../docs/principles.md).
- **묶음에 없는 이유.** 플러그인은 스킬 폴더만 설치하는데, 이 스킬은 프로젝트에 훅 · AGENTS.md 스니펫 · 기록 폴더를 놓아야 돈다.

## 한계

- 죽은 규칙(아무도 안 쓰는 규칙)은 세션에서 신호가 나오지 않아 잡지 못한다.
- 개인 메모리(auto memory 등)는 건드리지 않는다. 그쪽은 개인 선호, backlog는 프로젝트 하네스다.
- 검토 품질은 검토 모델에 달려 있다.
- SessionEnd 훅이 띄운 프로세스가 세션 종료 뒤 살아남는 동작은 실측에 의존한다. 바뀌면 주간 검토가 대신 잡아 늦어질 뿐 빠지지는 않는다.
