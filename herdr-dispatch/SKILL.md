# herdr-dispatch

herdr로 일을 위임할 때 **모델 / 추론 강도 / 권한** 세 가지를 의식적으로 고른다.

이 스킬은 herdr CLI 사용법을 담지 않는다. 그건 **herdr 공식 스킬**(`~/.agents/skills/herdr/SKILL.md`)이 정본이고, pane을 쪼개고 에이전트를 띄우는 명령은 거기서 읽는다. 이 스킬은 그 위에 **"무엇을 어떤 설정으로 띄울지"** 만 얹는다.

## 파일 안내

| 파일 | 언제 읽나 |
|---|---|
| `references/roles.md` | 매번. 세 축의 의미와 역할표 |
| `references/claude-cli.md` | claude를 띄울 때. 플래그 문법, 권한 모드, 별칭이 가리키는 버전 |
| `references/codex-cli.md` | codex를 띄울 때. 플래그 문법, 샌드박스·승인, fast 모드, 모델명과 은퇴일 |
| `references/verify.md` | 표를 재검증할 때만 (아래 "표가 낡았을 때") |
| `scripts/doctor.py` | `agent start`가 실패했거나 표가 의심스러울 때 첫 명령. 로컬에서 몇 초 안에 OK/WARN/FAIL |
| `scripts/codex-models.py` | codex 모델명이 의심스러울 때. 로컬 캐시의 모델 목록·추론 단계·기본값을 덤프 |

위임할 벤더의 파일만 읽으면 된다. 두 벤더에 동시에 띄울 때만 둘 다 읽는다.

## 0. 시작 전 — 두 가지 확인

```bash
test "${HERDR_ENV:-}" = 1                              # 아니면 중단
diff -q <(herdr --skill) ~/.agents/skills/herdr/SKILL.md  # 다르면 아래
```

herdr 스킬이 바이너리와 다르면 세션 시작 훅이 안 돌았다는 뜻이다. 사용자에게 알리고 `herdr-setup/sync-skill.sh` 실행을 제안한다. 낡은 herdr 스킬로 진행하면 없는 기능을 쓰거나 있는 기능을 놓친다.

## 1. 에이전트가 필요한지부터 묻는다

**명령을 돌리고 출력을 읽는 게 전부라면 에이전트를 띄우지 않는다.** 테스트·빌드·로그·스크립트는 `pane run` + `pane wait-output` + `pane read`로 끝난다. 에이전트를 띄우면 시작에만 수십 초가 들고, 승인 대기로 멈출 수 있고, 토큰을 쓴다.

에이전트가 필요한 경우는 **판단이 필요할 때** 뿐이다 — 코드를 읽고 의견을 내거나, 고치거나, 무엇을 볼지 스스로 정해야 할 때.

## 2. 일을 역할로 쪼갠다

`references/roles.md`의 역할표에서 가장 가까운 줄을 고른다. 표에 없으면 가장 비슷한 줄에서 시작하고, 같은 파일의 "어느 축을 올릴지" 규칙으로 조정한다.

## 3. 세 축을 정하고 근거를 남긴다

역할마다 모델·추론·권한을 정한다. **정한 이유를 한 줄로 남긴다** — 나중에 표를 고칠 때 이 기록이 근거가 된다.

```
reviewer: codex / gpt-6.1-sol / high / read-only / fast 끔
  → 리뷰는 엣지 케이스를 따라가야 해서 추론을 올림. 고치라고 부른 게 아니라 읽기 전용.
```

권한은 **항상 명시한다.** 안 정하면 pane이 첫 승인 프롬프트에서 `blocked`로 멈추는데, 그 UI는 사용자만 답할 수 있다 (herdr 스킬이 에이전트의 임의 응답을 금지한다). 권한은 두 갈래뿐이다:

- **읽기만 하면 되는 역할** — 읽기 전용으로 띄운다. claude는 `plan` 모드가 아니라 auto + 편집 도구 차단이다 — plan은 웹 조회마다 멈추고, 계획이 승인되면 편집이 풀린다. 차단이 bash까지 닿지는 않으므로 프롬프트에 "파일 수정·외부 게시 금지"를 적는다.
- **편집이 필요한 역할** — 승인을 모델이 대신 받는 모드를 켠다. 편집만 허용하는 중간 단계로 띄우지 말 것 — 파일은 고치는데 테스트·git 같은 bash 명령마다 멈춰서, 사용자가 프롬프트를 하나씩 답하게 된다.

각 갈래의 정확한 플래그와 함정(claude의 plan 모드, codex의 `-a never`, fast 모드)은 벤더 파일에 있다. 자동 검토를 켜도 프롬프트가 0이 되지는 않는다. 분류기·리뷰어가 위험하다고 판정하면 여전히 `blocked`이고, 그건 사용자에게 가져간다.

## 4. 띄우고 회수한다

herdr 스킬의 절차를 따르되, `--` 뒤에 3번에서 정한 플래그를 붙인다. 플래그 문법은 벤더 파일의 맨 위 표에 있다.

기억할 것 둘:

- `--no-focus` — 사용자 포커스를 뺏지 않는다
- `--cwd "$PWD"` — 작업 디렉터리는 상속되지 않는다. 명시해야 한다
- claude는 처음 보는 폴더에서 신뢰 확인 화면으로 멈춘다 — 이미 연 적 있는 레포 안에서 띄운다

## 5. 사용자에게 보고할 때

무엇을 어떤 설정으로 띄웠는지 한 줄로 밝힌다. 사용자가 "그건 과했다 / 부족했다"고 말할 수 있어야 표가 개선된다.

## 표가 낡았을 때

모델 이름은 낡는다 — codex 쪽은 실제 모델명이라 은퇴하고, claude 쪽은 별칭이라 이름은 남지만 가리키는 버전과 기본 effort가 바뀐다. 재검증은 두 경우에만 한다. 어느 쪽이든 **첫 명령은 `python3 -I scripts/doctor.py`** 다 — herdr 상태, 세 CLI의 플래그, codex 모델 캐시 대 역할표, 은퇴일, 전역 설정, 문서 확인일을 몇 초 안에 OK/WARN/FAIL로 낸다.

- **`agent start`가 모델 이름 때문에 실패했을 때.** doctor가 사라진 모델과 대체 후보를 짚는다. 그 자리에서 고치고 원래 일을 계속한다.
- **사용자가 요청했을 때** ("모델 업데이트 확인해"). doctor가 전부 OK여도 `references/verify.md`를 처음부터 끝까지 돌린다. doctor는 로컬에서 결정적으로 알 수 있는 것만 보고, 공식 문서 대조와 벤더별 pane 교차 확인(claude 쪽은 claude pane, codex 쪽은 codex pane)은 하지 못한다.

**주기적으로 문서를 감시하지 않는다.** 모델 이름이 틀리면 CLI가 즉시, 시끄럽게 실패하므로 감시자를 두는 것보다 실패 시점에 고치는 쪽이 정확하고 싸다. 다만 `codex-cli.md`의 은퇴일이 오늘에 가깝거나 지났으면 실패를 기다리지 말고 사용자에게 미리 알린다.

## 이 스킬이 하지 않는 것

- herdr CLI 사용법을 설명하지 않는다 — herdr 공식 스킬을 읽는다
- 사용자가 모델을 지정했으면 다시 고르지 않는다 — 지정된 대로 쓴다
- 승인 대기(`blocked`) 화면에 대신 답하지 않는다 — 사용자에게 가져간다
- 사용자가 만들지 않은 pane·탭·워크스페이스를 닫지 않는다
