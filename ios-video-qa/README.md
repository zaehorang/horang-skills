# ios-video-qa

iOS 앱을 시뮬레이터에서 **사람이 쓴 각본(md)대로** 조작하고, 영상 · 단계별 스크린샷 · 판정 근거 · 보고서를 남긴다. 판정이 정말 화면을 보고 내린 것인지 실행 뒤에 재현해서 검증한다.

## 왜 만들었나

AI에게 UI 시나리오를 맡기면 "통과"가 쉽게 나온다. 상수끼리 비교하거나, 앱 전체에 맞는 질의로 "있음"을 확인하거나, 후보가 여럿인데 아무거나 고르거나, 막히면 확인 항목을 슬쩍 약하게 바꾼다. 결과 표만 봐서는 이걸 알 수 없다.
그래서 합격 기준(각본)은 사람만 정하고, 모든 판정은 출처 있는 화면 읽기로만 하며, 엔진이 그 기록을 다시 돌려 "이 판정이 값 변화에 반응하는가"를 증명하게 했다.

## 무엇을 해주나

- 각본의 단계마다 앱을 조작하고, 영상과 단계 사진, 판정마다 그 순간의 화면 정보 · 사진을 남긴다.
- **실행 전 검사.** 출처 없는 판정, 덮지 않은 항목, 규칙 없는 후보 선택, 근거를 건드리는 어휘, 사람 승인 전 상태를 막는다.
- **실행 대조.** 항목마다 실행됨 / 건너뜀(사유) / 미실행. 근거 줄은 실행별 키로 서명해 위조한 줄을 세지 않는다.
- **재현 검증.** 저장한 화면 정보로 같은 판정을 다시 돌리고, 입력을 바꾼 변형에서 실패로 바뀌는지 본다. 화면을 보지 않는 판정은 "판정 결함"으로 막는다.
- **보고서와 리뷰 페이지.** 각본별 결과 · 근거 사진 · 영상 시각, "눈으로 확인" 항목의 사람 판단(미검토 / 정상 / 이상 / 판단 불가) 기록.
- **새 각본 pipeline.** 요소 찾기 → 질문 → 스크립트 → 검사 → 실행 → 검증 → 페이지(S0~S7). 사람이 정할 곳에서 멈춘다.

## 어떻게 쓰나

`dev` bundle에 있다 → [설치](../docs/install.md). 엔진은 이 폴더 전체이고, 앱 레포에 `qa/`를 만들어 쓴다. macOS와 Xcode 시뮬레이터가 필요하다.

> 이 앱에 영상 QA 설치해줘
> 영상 QA 돌려줘
> 새 QA 각본 만들어줘

절차는 [SKILL.md](SKILL.md), 명령 · 종료 코드 · 설정 키는 [references/commands.md](references/commands.md), 각본 · 스크립트 형식의 완성 예는 [examples/memo-app](examples/memo-app/qa)(가상의 메모 앱)에 있다. 엔진 자체 시험은 `scripts/qa test`이고 시뮬레이터 없이 돈다.

## 설계에서 정한 것

- **vendor 이름 규칙의 예외.** 이 repo는 본문에 도구 이름을 쓰지 않지만, 이 스킬은 시뮬레이터를 제어하는 것 자체가 목적이라 실행 도구(AXe) · `simctl` · Simulator 이름을 쓴다 → [원칙](../docs/principles.md). 대신 실행 도구를 부르는 곳은 `scripts/lib/driver/axe.sh` 한 파일로 모았고, 다른 도구로 바꾸려면 그 파일만 같은 함수 이름으로 다시 쓴다. 공유 페이지를 특정 서비스에 올리는 부분도 `scripts/pages/adapters/<이름>/` 안에만 둔다.
- **승인 · 답 · 판단은 사람만.** 반영은 대화형 터미널에서만, 에이전트 환경 변수가 없을 때만 된다. 승인 범위는 각본 전체와 그 스크립트다. 선택 규칙은 쓰임(각본 범위 · 질의 · 선택 방법)까지 승인한다.
- **승인 전에는 실행하지 않는다**(exit 5). 엔진 시험용 `QA_ALLOW_UNAPPROVED=1`은 결과를 "사람 승인 전"으로 크게 표시하고 통과로 끝내지 않는다.
- **판정 결함은 항상 막는다.** 예외 목록을 두지 않는다. 검증 불가 비율이 상한을 넘어도 막는다.
- **건너뜀은 통과가 아니다.** 사람이 승인한 스크립트의 건너뜀(사유 포함)만 통과로 센다.
- **사람마다 다른 값은 `qa.config`로.** 조건 이름 · 기기, 결과 보존 기간, 검증 불가 상한, 앱의 하루 경계 시각은 프로젝트가 정한다. 스킬은 "정해야 한다"만 말하고, 엔진에는 기본값만 있다.
- **설치형.** 앱 레포에 `qa/`를 만들고 결과를 그 아래에 쌓는다. 엔진 코드는 스킬 폴더에 그대로 두고 앱 레포에는 각본 · 스크립트 · 설정만 놓는다.

## 한계

- 사람 경로는 서명이 아니라 터미널 · 환경 변수 확인, 기록 체인, 스냅샷 비교로 지킨다. 같은 사용자 권한의 프로그램이 환경 변수를 비우고 터미널을 흉내 내면 통과할 수 있다. 막지 못하므로 에이전트 규칙으로 금지한다.
- 근거 서명 키는 실행이 끝난 뒤 결과 폴더에 남는다(나중에 `qa verify`를 다시 돌리려고). 실행 뒤에 근거를 바꾸는 것은 막지 못한다.
- 금지 어휘 검사는 정규식이다. 셸의 모든 우회를 막는다고 보장하지 않는다.
- 가림 검사는 화면 정보에 드러난 키보드 · 시트 · 알럿 · 팝오버까지만 본다. 화면 정보에 안 나오는 덮개는 모른다.
- 세로 iPhone 화면을 가정한다(밀기 · 키보드 위치 비율). iPad · 가로 화면은 지원하지 않는다. 화면 키보드는 한국어 팩만 기기에서 확인했다.
- 화면 키보드는 시뮬레이터 전역 설정이 필요해 Mac(사용자)당 한 번에 한 실행만 된다.
