# 각본 형식

각본(`cases/QA-NN-<영문>.md`)이 합격 기준이다. 파일 전체(머리 항목·행동·자동 확인·눈으로 확인·메모)가 승인 대상이다.

```markdown
# QA-01 메모 쓰기

한두 문장: 사용자가 무엇을 하려는 흐름이고, 끝나면 어떤 상태가 되는가.

- 명세: 없음
- 준비: 빈 목록
- 실행: 자동
- 입력: 화면 키보드
- 조건: 기본
- 화면: 목록, 편집
- 비교 제외: (사진 비교에서 뺄 영역)

| # | 행동 | 자동 확인 | 눈으로 확인 |
|---|---|---|---|
| 1 | '새 메모' 탭 | 편집 화면 제목 '새 메모' | 키보드가 올라오며 입력칸이 가려지지 않음 |
| 2 | [외부] … | … · … | |

## 메모
- 자유 메모(승인 대상)
```

## 머리 항목

키는 한국어가 기준이고 영어 별칭을 받는다. 값도 같다.

| 키 | 별칭 | 값 |
|---|---|---|
| 명세 | spec | 관련 명세 위치. 보고서에 표시 |
| 준비 | prep, state | `states.sh`의 `QA_STATES` 이름 |
| 실행 | run | 자동(auto) · 수동(manual) |
| 입력 | input | 화면 키보드(software keyboard) · 블루투스 키보드(hardware keyboard, bluetooth keyboard) · 없음(none) |
| 조건 | conditions, condition | `qa.config`의 `QA_CONDITIONS` 이름, 쉼표로 여럿 |
| 화면 | screens, screen | 관련 화면(소스) 이름. 보고서에 표시 |
| 비교 제외 | ignore, exclude | 사진 비교에서 뺄 것. 보고서에 표시 |

## 단계 표

- 번호는 1부터 차례로, 10단계 이하.
- 행동 앞의 `[외부]`(`[external]`)는 외부 서비스 결과에 좌우되는 단계. 그 단계의 자동 확인에 외부 값(숫자 등)을 넣으면 경고한다.
- 자동 확인 칸을 ` · `로 나눈 것이 확인 항목이다. 항목마다 ID가 붙는다: 정규화한 문구(줄끝·바깥 공백 제거)의 SHA-1 앞 8자리 + `#단계.순번`. `qa ids <ID>`로 본다.
- 문구가 바뀌거나 단계가 삽입·재배열되면 ID가 바뀌어 스크립트 연결이 끊기고, 각본이 바뀌었으므로 재승인이 필요하다.
- 자동 확인은 참·거짓으로 판정할 수 있게 쓴다("적절", "자연스럽게" 같은 말은 질문이 된다). 저장처럼 결과가 남아야 하는 일은 "눌렀다"로 끝내지 않고 다시 확인하는 단계를 둔다(목록에 보이는지, 다시 열어도 남는지).
- 수동 각본은 `| # | 행동 | 확인 |` 세 칸이다.

## 메모

`## 메모`(`## Notes`) 아래의 줄. 선택 규칙의 뜻을 사람이 읽게 한 줄로 남겨 둘 수 있다.
