# 실행 대조와 재현 검증

## 근거 줄과 서명

판정 하나마다 덮는 항목마다 한 줄이 `evidence.jsonl`에 쌓인다(덮어쓰지 않는다): 판정 ID, 항목, 단계, 판정 함수, 판정기 버전, 입력과 그 출처(질의·화면 정보 파일·트리 경로·후보·영역), 결과, 사진, 오류, 비용.
실행마다 새 키를 만들어 판정기에게만 넘기고, 판정기가 줄마다 HMAC 서명(`mac`)을 단다. 스크립트는 키를 읽지 못한다(실행 전 검사가 막는다). 실행이 끝나면 키를 결과 폴더의 `.evidence-key`에 남긴다.
서명이 없거나 맞지 않는 줄은 실행 대조와 재현 검증 모두 받지 않는다.

## 실행 대조(coverage.json)

항목마다 실행됨(서명된 판정 줄 있음) · 건너뜀(서명된 `skip` 줄만) · 미실행. 각본 결과:
- 스크립트가 0이 아닌 코드로 끝남 → `fail`
- 미실행 항목이나 버린 근거 줄이 있음 → `incomplete`
- 건너뜀이 있고 스크립트가 사람 승인 상태가 아님 → `skipped`
- 그 밖 → `pass`

## 재현 검증(verify.json)

앱을 다시 돌리지 않고 저장한 화면 정보로 같은 판정 함수를 다시 돌린다.
1. 재현 일치: 같은 질의·같은 판정기 버전으로 다시 판정한 결과가 기록과 같은가.
2. 유효한 변형의 실패: 입력을 바꾼 변형에서 실패로 바뀌는가. 변형은 적용 전에 유효한지 본다(바꿨더니 질의가 다른 요소를 고르면 부적합).

| 판정 | 변형 |
|---|---|
| present | 맞은 요소를 모두 지움, 질의 문구를 없는 문구로 |
| gone | 이 실행(과 최근 3회)에서 실제로 보였던 같은 요소를 다시 넣음. 한 번도 없었으면 결함(항상 통과하는 판정) |
| visible · tappable | 요소를 화면 밖으로, 시트가 요소를 덮게, 키보드가 덮게, (tappable) 비활성으로 |
| check_* | 읽은 요소의 값을 결과가 뒤집히는 값으로 바꾸고 같은 질의로 다시 읽음. 숫자는 숫자로 |

항목 결과: 검증됨 · 검증 불가(화면 정보·속성 없음, 원래 판정이 통과가 아님, 판정기 버전이 다름) · 변형 부적합 · 판정 결함(재현이 다름, 변형에도 통과, 앱 전체에 맞는 질의, 같은 요소를 두 번 읽음, 읽은 값이 질의 조건에 묶임) · 건너뜀 · 미실행.

## 막는 조건

다음 중 하나라도 있으면 실행을 통과로 보지 않는다(`qa run` exit 1).
- 판정 결함 1개 이상(예외 없음)
- 근거 위조 의심(서명이 맞지 않는 줄), 서명 키 없음
- 검증 불가 비율(검증 불가 + 변형 부적합 + 건너뜀 + 미실행) / 전체 항목이 상한을 넘음: 각본별 `QA_UNVERIFIABLE_CASE_MAX`(기본 30%), 전체 `QA_UNVERIFIABLE_RUN_MAX`(기본 20%)

검증 불가가 많다는 것은 출처가 빠진 판정이 많다는 뜻이다. 스크립트를 고친다(각본을 약하게 만들지 않는다).
