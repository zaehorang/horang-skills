# deck-assets

이미지는 재생성이 잦다. "다시 만들어 줘" 가 세 번 오면 컨셉을 세 번 말로 다시
설명하게 된다. **컨셉을 파일에 고정해 두고 거기서 다시 만든다.**

## 이미지가 텍스트를 이기는 자리

아무 장에나 넣지 않는다. 다음 둘일 때만 이긴다.

- **공감해야 하는 상황** — 문제 장면. 같은 일을 두 사람이 따로 하고 있는 그림이
  "중복 작업이 발생한다" 는 문장보다 빠르다
- **공간적 개념** — 흩어짐 → 모임, 갈라짐, 순환. 글로 쓰면 길고 그림이면 한눈에 들어온다

주장·수치·상태는 이미지로 만들지 않는다. 패턴으로 배치한다.

## 산출물 · ASSETS.md

작업 폴더에 둔다. 이미지를 처음 만들 때 같이 쓰고, 재생성할 때 여기서만 읽는다.

```markdown
## 컨셉
캐릭터: (예 — 호랑이 직원. 사람 캐릭터는 쓰지 않는다)
톤: (선화 기반, 배경 단색, 덱의 레드 계열 포인트)
금지: (사실적 명암, 텍스트 삽입, 복잡한 배경)

## 레퍼런스
- path/to/reference1.png — 구도 참고
- path/to/reference2.png — 채색 톤 참고

## 자산
| 파일 | 쓰는 장 | 무엇을 보여주는가 | 프롬프트 요지 |
|---|---|---|---|
```

**재생성 요청이 오면 컨셉과 금지 항목은 유지하고 요청받은 것만 바꾼다.**
캐릭터가 바뀌면 앞뒤 장의 이미지가 다른 발표처럼 보인다.

## 규칙

### 외부 서비스는 로고로 식별시킨다

Slack·Notion·GitHub 처럼 청중이 아는 서비스를 그릴 때, 색과 모양만으로는 구분되지
않는다. 로고를 넣는다. 발표 중에 "저게 뭔지" 를 설명하는 데 시간을 쓰지 않게 된다.

### 상황 일러스트는 말풍선이 붙은 한 장면

컷을 여러 개로 나누면 슬라이드에서 각 컷이 작아져 읽히지 않는다. 한 장면 + 말풍선
한두 개. 말풍선 안의 글자도 슬라이드 높이의 2% 하한을 지켜야 한다.

### 제품 화면은 전체를 캡처하지 않는다

전체 화면을 그대로 넣으면 슬라이드 위에서 모든 컴포넌트가 작아져 아무것도 읽히지
않는다. **말하려는 관심 영역만 잘라 낸다.** 필요하면 두 영역을 따로 잘라 나란히 둔다.

잘라 낸 뒤 그 안의 글자가 원본 대비 어느 비율로 들어가는지 확인한다. 2% 하한은
생성된 이미지 안의 글자에도 그대로 적용된다 — 검사기는 이미지 속 글자를 못 잡는다.

## 생성

사용자가 이미지 생성 도구를 지정했으면 그것으로 만든다. 지정이 없으면 **자리표시자를
두고 무엇이 필요한지 말한다.** 만들어 내지 않는다.

만든 이미지는 덱 폴더의 `assets/` 안에 둔다. 바깥을 참조하면 폴더만 옮길 때 깨진다.

## 경계

- 이 단계는 `deck-build` 안에서 필요할 때만 돈다. 독립 게이트가 아니다.
- 컨셉을 바꾸는 것은 사용자의 결정이다. 임의로 바꾸지 않는다.
