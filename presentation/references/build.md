# deck-build

승인된 `FLOW.md` + `SCRIPT.md` 를 `<skill-dir>/assets/starter/presentation.html` 위에
슬라이드로 옮긴다.

**둘 다 없으면 만들지 않는다.** 먼저 `deck-plan`, `deck-narrate` 를 쓰라고 안내한다.
대본 없이 화면부터 만들면 레이아웃이 말을 끌고 간다.

## 무엇을 옮기는가

`SCRIPT.md` 각 장의 **"화면에 둘 것"만** 옮긴다.
**"말로만 할 것"은 슬라이드에 넣지 않는다.**

대본 문장을 그대로 슬라이드에 붙이지 않는다. 슬라이드는 대본이 아니라
**청중이 3초 안에 결론을 잡게 돕는 근거**다. 발화체 문장은 구절로 줄인다.

```
기존 지침·규칙·자동화·스킬을 못 찾아 다시 만듭니다   (23자)
→ 찾지 못해 다시 만든다                              (11자)
```

## 절차

### 1. 템플릿 복사

```bash
cp <skill-dir>/assets/starter/presentation.html <작업폴더>/presentation.html
mkdir -p <작업폴더>/assets
cp <skill-dir>/assets/starter/assets/* <작업폴더>/assets/
```

**CSS와 엔진은 건드리지 않는다.** 실측으로 검증된 자산이다.
색·간격·폰트를 손대야 할 이유가 생기면 먼저 사용자에게 이유를 말하고 확인받는다.

### 2. 패턴 선택

템플릿의 패턴 A~M 중에서 고른다. 새 레이아웃을 즉흥으로 만들지 않는다.
각 패턴 주석에 **정보 예산**이 적혀 있다. 예산을 넘기면 글자를 줄이는 게 아니라 **내용을 줄인다.**

| 상황 | 패턴 |
|---|---|
| 표지 | A |
| 두 개념 대비 | B |
| 장면 + 서술 | C |
| 문제 ↔ 대응 매핑 | D |
| 우선순위 있는 목록 | E (균등 나열은 "다 똑같이 중요하다"는 뜻이 된다) |
| 역할 분담 | F |
| 단계별 계획 | G |
| 구성요소 + 구현 상태 | H |
| 지표 + 결정 요청 | I |
| 두 동작 시점 | J |
| 행동 흐름 + 표 | K |
| 사용자 여정 | L |
| **제품 화면 + API·데이터 콜아웃** | **M** |

### 3. 이미지가 필요하면

상황 일러스트나 제품 화면 캡처가 들어가는 장은 [assets.md](assets.md) 를 읽고 진행한다.
컨셉은 `ASSETS.md` 에 고정하고, 캡처는 전체 화면이 아니라 관심 영역만 잘라 쓴다.

### 4. 상태 토큰 규칙

배지는 **구현 상태 하나의 축**에만 쓴다.

```
badge          회색 = 현재 확인됨   ↔  .service.confirmed
badge plan     레드 = 제안          ↔  .service.proposed
badge next     빈원 = 예정          ↔  .service.backlog
```

범례 색과 카드 색은 반드시 같은 뜻이어야 한다.
역할·단계 표시는 `.role-tag`, `.phase` 처럼 **다른 토큰**을 쓴다.

페이지 번호는 `<span class="page"></span>` 로 비워 둔다. 엔진이 채운다.

### 5. 내부 검토 — 결과를 내기 전에 한 번 돈다

초안을 만든 직후, 사용자에게 보여주기 **전에** 반드시 한 바퀴 돈다.

```bash
python3 <skill-dir>/scripts/deck_verify.py <작업폴더>/presentation.html
```

오류가 나오면 고치고 다시 돌린다. **오류 0이 될 때까지 반복한다.**
그 뒤 스스로 아래를 점검하고, 걸리는 게 있으면 고친 다음 결과를 낸다.

- SCRIPT 의 "화면에 둘 것" 이 실제 슬라이드에 다 들어갔는가
- **"말로만 할 것" 이 슬라이드에 새어 들어가지 않았는가**
- 대본 문장을 그대로 옮긴 텍스트 덤프 슬라이드가 없는가
- 한 장이 두 질문에 답하고 있지 않은가
- 균등 나열이 우선순위를 지워버리지 않았는가
- `제안`을 `확인됨`처럼 보이게 쓴 곳이 없는가

### 6. 보고

사용자에게는 **검사를 통과한 결과만** 보여준다. 무엇을 만들었고, 내부 검토에서
무엇을 고쳤는지 짧게 함께 말한다.

## 경계

- 장 배열을 바꾸지 않는다. 순서 변경은 `deck-plan` 으로 FLOW.md 부터 고친다.
- 대본을 고치지 않는다. 대본이 화면과 어긋나면 말로 알리고 `deck-polish` 로 넘긴다.
- 사용자가 "피드백만" 또는 "확인만" 이라고 하면 파일을 고치지 않고 말로 답한다.
- 이미지가 없으면 만들어내지 않는다. 자리표시자를 두고 무엇이 필요한지 말한다.
