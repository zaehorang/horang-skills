# deck-build

승인된 `FLOW.md` + `SCRIPT.md` 를 `<skill-dir>/assets/starter/presentation.html` 위에
슬라이드로 옮긴다.

**둘 다 없으면 만들지 않는다.** 먼저 `deck-plan`, `deck-narrate` 를 쓰라고 안내한다.
대본 없이 화면부터 만들면 레이아웃이 말을 끌고 간다.

## 무엇을 옮기는가

`SCRIPT.md` 각 장의 **"화면에 둘 것"만** 옮긴다.
**"말로만 할 것"은 슬라이드에 넣지 않는다.**

대본 문장을 그대로 슬라이드에 붙이지 않는다. 슬라이드는 대본이 아니라
**청중이 3초 안에 결론을 잡게 돕는 근거**다. 발화체 문장은 구절로 줄인다.

```
기존 지침·규칙·자동화·스킬을 못 찾아 다시 만듭니다   (23자)
→ 찾지 못해 다시 만든다                              (11자)
```

## 절차

### 1. 템플릿 복사

```bash
cp <skill-dir>/assets/starter/presentation.html <작업폴더>/presentation.html
mkdir -p <작업폴더>/assets
cp <skill-dir>/assets/starter/assets/* <작업폴더>/assets/
```

**간격·폰트·패턴 CSS와 엔진은 건드리지 않는다.** 실측으로 검증된 자산이다.
손대야 할 이유가 생기면 먼저 사용자에게 이유를 말하고 확인받는다.
색은 예외다. 아래 [색 바꾸기](#색-바꾸기)의 세 자리에서만 바꾼다.

### 2. 패턴 선택

**본문은 제목 바로 아래 같은 위치에서 시작한다.** 장을 넘겨도 같은 종류의 요소가 같은 자리에 있어야
청중의 시선이 튀지 않는다. 내용이 적은 장은 아래가 비는 게 정상이다 — 가운데로 끌어내리지 않는다.
한 덩어리를 화면 가운데 두는 장(표지, 핵심 숫자 V)만 `.content.center`를 붙인다.

템플릿의 패턴 A~V 중에서 고른다. 새 레이아웃을 즉흥으로 만들지 않는다.
각 패턴 주석에 **정보 예산**이 적혀 있다. 예산을 넘기면 글자를 줄이는 게 아니라 **내용을 줄인다.**

| 상황 | 패턴 |
|---|---|
| 표지 | A (이미지가 없으면 `.cover-content.text-only` 1열 변형) |
| 목차 · 덩어리가 바뀔 때 진행 지도 | U |
| 두 개념 대비 | B |
| 장면 + 서술 | C |
| 문제 ↔ 대응 매핑 | D |
| 우선순위 있는 목록 | E (균등 나열은 "다 똑같이 중요하다"는 뜻이 된다) |
| 역할 분담 | F |
| 단계별 계획 | G |
| 구성요소 + 구현 상태 | H |
| 지표 + 결정 요청 | I |
| 두 동작 시점 | J |
| 행동 흐름 + 표 | K |
| 사용자 여정 | L |
| **제품 화면 + API·데이터 콜아웃** | **M** |
| **전폭 분석 그림 + 결론 한 줄** | **N** |
| **두 흐름이 주고받는 구조 (갈라짐·합쳐짐·왕복)** | **O 레인 흐름** |
| **같은 뼈대에 무엇이 더해지는가** | **P 전/후 구조도** |
| **구조를 순서대로 짚어 가는 설명** | **Q 번호 구조도 + 범례** |
| **문제 하나 ↔ 해결 하나, 문장이 긴 목록** | **R 가로 행 매핑** |
| **코드를 단계별로 설명** | **S 코드 워크스루** |
| 여러 항목을 같은 기준으로 나란히 | T 데이터 표 |
| 발표를 대표하는 숫자 하나 | V 핵심 숫자 |

**장 종류로 고르려면 [examples/gallery/index.html](../examples/gallery/index.html)을 연다.**
표지·목차·개념 설명·코드 설명·비교·표·로드맵·결정 요청 등 발표에 자주 나오는 장 22가지를
한 주제로 채워 두었다. 맞는 장의 `<section>`을 갤러리 `presentation.html`에서 복사해 내용만 바꾼다.

요지 박자가 "A에서 B로 간다 · 여기서 갈라진다 · 다시 돌아온다"처럼 **공간 이동**이면
카드가 아니라 구조도(O·P·Q)를 쓴다. 칩을 화살표로 한 줄 잇는 J는 직선 흐름에만 쓴다.

패턴 A는 이미지 유무에 맞춰 2열 또는 1열 변형을 고른다. 이미지가 없을 때는
`.cover-visual-wrap`을 빼고 `.cover-content`에 `text-only`를 붙인다.
빈 헤더나 표지용 자리표시자 없이도 제목·부제·한 문장으로 완성한다.

패턴 N은 보고서의 가로로 긴 차트(예: 1350×450)를 온전히 보여줄 때 쓴다.
`.analysis-figure`에 그림 하나를 넣고, 아래에 `.final-line` 결론 한 줄과
`.figure-source` 출처 한 줄을 둔다. `object-fit:contain`과 원래 색을 유지한다.
제목은 한 줄로 압축하고 이미지 안 글자도 축소 후 2% 하한을 확인한다.
예시 데이터 그림은 실제 분석 그림으로 교체한다.

### 제목 쓰기

**제목은 그 장의 결론이다(두괄식).** 무엇에 관한 장인지는 제목 위 kicker가 맡고, 제목은 청중이 가져갈 판단을 쓴다. 제목만 이어 읽어도 발표 줄거리가 되어야 한다. FLOW의 `핵심 주장`을 줄여 쓴다.

| 규칙 | 피할 것 | 쓸 것 |
|---|---|---|
| 명사형·개조식으로 끝낸다 | 정답률이 54%에서 81%로 올랐다 | 정답률 54% → 81% 상승 |
| 대비는 "A는 X, B는 Y" 대구로 | 에이전트는 찾고, 사람은 결정한다 | 찾기는 에이전트, 결정은 사람 |
| 주제 이름만 쓰지 않는다 | 로드맵 | 위키에서 시작해 한 분기 안에 전사 확대 |
| 수량은 아라비아 숫자와 단위로 | 문제 다섯에 기능 다섯 | 문제 5개에 기능 5개를 1:1로 대응 |

- 한 줄에 담는다(50px 기준 약 20자). 넘치면 조사·수식어를 덜거나 장을 나눈다.
- 표지 제목(h1)은 질문형·문장형도 된다. 본문의 결론 문장(`.final-line`)과 대본은 문장으로 쓴다.
- `deck_verify`가 "~다·~요·~까"로 끝나는 장 제목을 `title-style` 경고로 짚는다.

### 줄바꿈

**캔버스가 1280×720으로 고정이라 줄이 어디서 나뉘는지는 어느 화면에서나 같다.** 그러니 두 줄 이상 되는 문장(제목·리드·결론·카드 설명·목록)은 브라우저에 맡기지 말고 끊을 자리를 정한다.

- **의미 단위에서 끊는다.** 쉼표 뒤, 주어부와 서술부 사이, "→" 앞, 조건절("~했을 때,") 뒤. 꾸미는 말과 꾸밈 받는 말, 숫자와 단위, 영문 용어 묶음(`zero-shot`, `pi0.5 base`, `6/10 → 9/10`)은 같은 줄에 둔다.
- **모양을 본다.** 줄 길이가 비슷하거나 윗줄이 조금 긴 모양이 안정적이다. 마지막 줄에 한두 어절만 남으면 앞에서 끊는다.
- **방법.** 끊을 자리에 `<br>`를 넣는다. 끊기면 안 되는 묶음은 `<span class="nobr">`로 감싼다. 템플릿은 어절 단위 줄바꿈(`keep-all`)과 고아 줄 방지(`text-wrap:pretty`)를 기본으로 건다.
- **세 줄이 넘으면 끊기 전에 줄인다.**
- **좁은 칸(3열 이상 카드·표 칸)에서는 묶기를 아낀다.** `nobr` 묶음이 많으면 줄 끝이 들쭉날쭉하고 짧은 줄이 혼자 남는다. 오른쪽 끝이 한 어절 이상 들쭉날쭉하면 묶기를 풀고 문장을 줄인다 — 좁은 칸의 글은 두세 줄 안에서 끝나게 쓴다.

| 피할 것 | 쓸 것 |
|---|---|
| 엔드포인트별 VLA(pi0.5)의 ego trajectory 분포를 확인했을 때, base pi0.5 / 만 reward guidance로 조작이 가능해 보 / 임. | 엔드포인트별 VLA(pi0.5)의 ego trajectory 분포를 확인했을 때,`<br>`base pi0.5만 reward guidance로 조작이 가능해 보임. |
| 가운데 — pi0.5 LIBERO fine-tune (this scene: zero- / shot) | 가운데 — pi0.5 LIBERO fine-tune`<br>`(this scene: `<span class="nobr">`zero-shot`</span>`) |

`deck_verify`가 마지막 줄에 한두 글자만 남은 곳을 `orphan` 경고로 짚는다. `<br>`을 넣은 요소는 작성자가 정한 끊김으로 보고 건너뛴다.

목록 항목 사이는 줄간격보다 넓다(`li + li` 0.45em). 두 줄짜리 항목과 다음 항목이 한 덩어리로 붙어 보이지 않게 하려는 것이다.

### 빈 공간 — 위에 몰리지 않게

본문은 제목 바로 아래에서 시작한다(장을 넘겨도 같은 자리). 그 대신 **내용이 적어 본문 아래가 3분의 1 넘게 비면 채운다.** 가운데 정렬로 풀지 않는다(표지·핵심 숫자만 예외).

1. **키운다** — `<div class="content roomy">`. 본문 26px · 라벨 20px · 카드 제목 32px로 한 단계 오르고, 표 행·카드 여백·구조도 간격·와이어프레임도 함께 커진다. 넣은 뒤 넘침(`overflow`)이 없는지 확인한다. **넘치면 중간 단계 `roomy-sm`**(본문 23px · 라벨 18px · 카드 제목 28px)을 쓴다.
2. **합친다** — 같은 질문에 답하는 옆 장과 한 장으로.
3. **더한다** — 주장을 받치는 그림·캡처가 있으면 옆에 둔다. 장식용 그림은 넣지 않는다.

**카드 틀만 늘려 채우지 않는다.** 경고는 사라져도 글은 카드 위쪽에 남아, 빈 곳이 카드 안으로 옮겨갈 뿐이다. 셋 다 안 맞으면 여백을 그대로 두는 편이 낫다.

`deck_verify`가 본문이 위에 몰리고 아래가 33% 넘게 비면 `empty-below` 경고를 낸다.

### 구조도 그리기 (O · P · Q)

노드는 CSS 그리드 칸에 놓고, 선은 엔진이 그린다. 좌표를 손으로 찍지 않는다.

```html
<div class="dg">
  <div class="dg-grid" style="--cols:3">
    <div class="dg-node" id="a" style="--x:1;--y:1">요청</div>
    <div class="dg-node new" id="b" style="--x:2;--y:1"><span class="dg-num">1</span>판단</div>
    <div class="dg-node" id="c" style="--x:2;--y:2">실행</div>
  </div>
  <i class="dg-edge" data-from="a" data-to="b"></i>
  <i class="dg-edge" data-from="b" data-to="c" data-kind="dashed" data-label="행동" data-offset="-28"></i>
  <i class="dg-edge" data-from="c" data-to="b" data-offset="28"></i>
</div>
```

| 부품 | 뜻 |
|---|---|
| `.dg-lane.tone-a/b` + `.dg-lane-title` | 단계·시점 하나를 묶는 레인. 모서리에 이름 |
| `.dg-node` · `.pill` · `.soft` · `.new` | 노드 · 시작/끝 · 이미 있는 것(흐림) · 새로 생긴 것(칠함) |
| `.dg-group` + `<small>` | 노드를 감싸는 점선 묶음 |
| `.dg-note` | 레인의 ✓ 한 문장. 선이 지나는 자리면 `.dg-grid` 안 빈 칸에 `--x:3 / 6` 으로 넣는다 |
| `.dg-num` | 번호. 노드 안과 `.dg-legend` 에 같은 숫자를 둔다 |
| `.dg-edge` | 선 한 개. `data-from` · `data-to` 필수 |

선 속성: `data-kind` solid·dashed / `data-route` auto·straight·curve·elbow /
`data-from-side`·`data-to-side` t·r·b·l / `data-offset` 왕복선 간격 /
`data-arrow` end·both·none / `data-label` · `data-label-at`(0~1).

선 문법은 **실선 = 주 흐름, 점선 = 되돌아감·조건·대응** 하나뿐이다. 레인을 건너는 왕복선은
두 노드를 같은 열에 두고 `data-offset` 을 ±로 주면 곧은 두 줄로 나란히 선다.
번호는 **SCRIPT 박자 순서**를 따른다. 발표자가 번호만 따라 말하면 되게 한다.
예산은 [layout-budget.md](layout-budget.md#구조도-예산)를 따른다.

### 코드 설명하기 (S)

세 영역이 **같은 곳**을 가리키게 한다.

- **단계 레일** `.walk-rail` — 전체 단계 5개 이하. 지금 단계에 `.now`를 붙이고 그 단계만 하위 2줄을 펼친다.
  같은 레일을 코드 장마다 복사하고 `.now`만 옮기면 진행 지도가 된다. kicker에 `CODE · 3 / 5`처럼 위치를 적는다.
- **코드** `<pre class="code"><code>` — 설명할 줄만 12줄까지, 한 줄 80자 안. 필요 없는 줄은 지우거나 `…`로 접는다.
  `.k` 키워드 · `.s` 문자열 · `.c` 주석. 짚을 줄은 `<span class="hl">…<span class="dg-num">1</span></span>`로 감싼다.
  강조 묶음은 1~2곳이다. 다 칠하면 아무것도 안 짚은 것이 된다.
- **결과** `.code-out` — 강조 줄과 같은 번호로 "이 줄이 무엇을 바꾸는가"를 2~3칸에 쓴다.
  대신 작은 구조도(`.dg`)로 "그래프의 어디인가"를 보여줄 수 있다. 둘 중 하나만 둔다.

`<pre>` 안의 줄바꿈과 들여쓰기는 그대로 화면에 나온다. HTML 들여쓰기에 맞춰 `<pre>`를 들여 쓰지 않는다.
글자를 줄여 맞추지 않는다. 넘치면 `code-overflow` 오류, 12줄을 넘으면 `code-budget` 경고가 난다.

### 색 바꾸기

**발표 성격에 맞는 테마를 고른다.** 기본은 clay이고, 사용자가 색이나 발표 성격을 말하지 않으면 바꾸지 않는다.
테마별 팔레트와 대표 장이 어떻게 보이는지, 라이트·다크가 어떻게 다른지는 [examples/gallery/themes.html](../examples/gallery/themes.html)에서 테마를 하나씩 골라 본다.

**모드는 라이트(기본, 흰 바탕)와 다크 두 가지다.** 밝은 회의실·인쇄·PDF 배포는 라이트, 어두운 강당·대형 화면·개발자 행사는 다크가 눈이 편하다. **회의실 빔프로젝터는 라이트를 기본으로 한다** — 밝은 방의 프로젝터는 어두운 계조를 뭉개 다크의 카드·선이 사라진다.
다크는 `data-mode="dark"`를 어느 테마에나 겹쳐 쓴다. 중립색(바탕·카드·선·글자)은 테마마다 색조를 맞춘 `--paper-dm` … `--ink-dm` 값을 쓰고, 다크 바탕에서 어두워 보이는 강조색은 `--accent-dm`으로 밝힌다. 본문은 바탕 대비 10~13:1, 제목은 15:1 아래로 두어 순백 번짐을 피한다.

| 테마 | 어울리는 발표 |
|---|---|
| `clay` (기본, 테마 없음) | 제안서·결과 보고. report 보고서와 같은 톤 |
| `ocean` | 기술 설명·아키텍처·데이터 리뷰 |
| `duo` | 강의·교육·비교. 남색 갈래 A, 자홍 강조가 분명 |
| `forest` | 운영 현황·성과 보고 |
| `signal` | 피치·키노트·외부 발표. 검정·빨강 고대비 |

색은 세 자리에서만 바꾼다. 패턴 CSS 안에 색 값을 쓰면 `deck_verify`가 `palette` 경고를 낸다.

| 범위 | 방법 |
|---|---|
| 덱 전체 | `<html lang="ko" data-theme="ocean">` |
| 다크 모드 | `<html lang="ko" data-theme="ocean" data-mode="dark">` — 어느 테마와도 겹쳐 쓴다. 한 장에만 걸 수도 있다 |
| 덱 전체, 새 색 | `[data-theme="이름"]{…}` 블록을 하나 더해 그 이름을 건다 |
| 한 장 | `<section class="slide" data-theme="duo">` |
| 한 요소 | `style="--c:#2F6FB0;--c-soft:#E2ECF6"` (레인·노드·선·행 매핑 칸) |
| 파일을 고치지 않고 미리 보기 | 주소에 `?theme=duo` · `?mode=dark` |

테마가 달라도 **역할은 같다.** 색 하나가 뜻 하나만 맡는다.

| 역할 | 토큰 | 쓰는 곳 |
|---|---|---|
| 강조 — 한 장에 한 곳 | `--accent` · `-dark` · `-soft` | 결론 한 줄, `.new` 노드, 짚는 행(`.hot`), 지금 단계 |
| 갈래 — 이쪽 / 저쪽 | `--tone-a` · `--tone-b` (+ `-soft`) | 레인 둘, 전/후 패널, 행 매핑 좌/우. 기본 a = 회색, b = 먹색 — **어떤 테마에서도 강조색이 아니다** |
| 구현 상태 | `--status-done` · `--status-plan` · `--status-next` | 배지·`.service` 카드. **강조색과 다른 색** |
| 코드 블록 | `--code-bg` · `--code-key` · `--code-str` · `--code-dim` | 패턴 S |

**글자에는 `--accent-dark`, `--accent`는 선·면에만 쓴다.** 연한 강조색 글자는 테마에 따라 대비가 4.5:1 아래로 떨어진다.

**글자색은 둘로 나눈다.** 읽어야 하는 문장(리드·카드 설명·범례·콜아웃·결과 칸)은 `--body`, 라벨·메타·화살표·"지난 것"만 `--muted`. 회색으로 문장을 쓰면 프로젝터에서 묻힌다. `--muted`도 카드 면 위 6:1 이상이 되게 잡혀 있다.

**글자 강조** — KPI 숫자나 핵심 어구를 `<span class="accent">`로 칠한다. 라이트는 `--accent-dark`, 다크·어두운 장은 `--accent-on-dark`로 자동으로 바뀌고, 본문 안에서는 굵기도 함께 오른다.

- 한 장에 한 곳, 짧게(숫자 하나 또는 8자 안팎 어구). 문장 전체는 `.final-line`의 몫이다.
- "짚는 곳 하나"에 포함해 센다. 짚는 요소(`.hot` 카드·행, `.new` 노드, `.stat-num`)가 있으면 **같은 대상**만 칠한다 — 15장 "54% → **81%**"는 큰 숫자와, 10장 "**근거 열기**"는 짚는 API 행과 같은 대상이다.
- 제목이나 본문 중 한 곳. 제목에 `.final-line`과 같은 말을 칠하지 않는다.
- 숫자를 우선한다. 번호·라벨·갈래에는 쓰지 않는다.
- 모든 장에 칠하지 않는다. 짚을 대상이 없는 장은 먹색만으로 둔다. `deck_verify`가 한 장 두 곳 이상을 `accent-text` 경고로 짚는다.

새 테마 점검 — 팔레트 장(`examples/gallery/palette.html?theme=이름`)이 대비를 계산해 보여준다.

| 짝 | 기준 |
|---|---|
| 바탕 위 `--accent-dark` 글자 · `--accent-soft` 위 `--accent-dark` 글자 · `--accent-dark` 위 흰 글자 | 4.5:1 |
| 먹색 바탕 위 `--accent-on-dark` (표지 kicker·코드 키워드) | 4.5:1 |
| 다크 바탕 위 `--accent-on-dark` 글자 · `--accent` 선·면 | 4.5:1 · 3:1 |
| `--accent-soft` 위 보조 글자 — `--muted` 대신 `--body`를 쓴다 | 4.5:1 |
| 바탕 위 `--accent` 선·면 · `--status-next` 점선 | 3:1 |
| 코드 바탕 위 `--code-key` | 4.5:1 |
| `--accent`와 `--status-plan` | 색상(hue)이 달라야 한다 |
| 다크 바탕 위 `--accent-dm` 선 | 4:1 안팎 — 어두운 강조색은 밝힌 값을 준다 |
| 카드 위 `--muted` 보조 글자 · 다크 카드/바탕 면 단차 | 4.5:1 · 1.18 이상 |

`deck_verify`의 `text-contrast`는 보통 글자 4.5:1, 큰 글자(24px 이상 또는 굵은 19px 이상) 3:1 아래를 오류로 낸다. 그라데이션 카드(강조 카드)와 SVG 안 글자는 건너뛴다. 새 테마를 만들면 팔레트 장의 "강조 바탕 위 강조 글자"를 라이트·다크 둘 다 확인한다.

### 3. 이미지가 필요하면

상황 일러스트나 제품 화면 캡처가 들어가는 장은 [assets.md](assets.md) 를 읽고 진행한다.
컨셉은 `ASSETS.md` 에 고정하고, 캡처는 전체 화면이 아니라 관심 영역만 잘라 쓴다.

### 4. 상태 토큰 규칙

배지는 **구현 상태 하나의 축**에만 쓴다.

```
badge          --status-done 먹색   = 현재 확인됨  ↔  .service.confirmed
badge plan     --status-plan        = 제안        ↔  .service.proposed
badge next     빈 원(--status-next) = 예정        ↔  .service.backlog
```

"제안" 색은 강조색과 다르다. 강조(주황 등)는 "여기를 봐라" 한 곳에만 남긴다.

범례 색과 카드 색은 반드시 같은 뜻이어야 한다.
역할·단계 표시는 `.role-tag`, `.phase` 처럼 **다른 토큰**을 쓴다.

페이지 번호는 `<span class="page"></span>` 로 비워 둔다. 엔진이 채운다.

### 5. 내부 검토 — 결과를 내기 전에 한 번 돈다

초안을 만든 직후, 사용자에게 보여주기 **전에** 반드시 한 바퀴 돈다.

```bash
python3 <skill-dir>/scripts/deck_verify.py <작업폴더>/presentation.html
```

오류가 나오면 고치고 다시 돌린다. **오류 0이 될 때까지 반복한다.**
그 뒤 스스로 아래를 점검하고, 걸리는 게 있으면 고친 다음 결과를 낸다.

- SCRIPT 의 "화면에 둘 것" 이 실제 슬라이드에 다 들어갔는가
- **"말로만 할 것" 이 슬라이드에 새어 들어가지 않았는가**
- 대본 문장을 그대로 옮긴 텍스트 덤프 슬라이드가 없는가
- 한 장이 두 질문에 답하고 있지 않은가
- 균등 나열이 우선순위를 지워버리지 않았는가
- 구조도의 선이 노드·문장을 가로지르지 않는가 (스크린숏이나 PDF로 직접 본다)
- 갤러리에서 복사한 장의 견본 안내(`<span class="guide">`)를 실제 문구로 바꿨는가
- `제안`을 `확인됨`처럼 보이게 쓴 곳이 없는가

### 6. 보고

사용자에게는 **검사를 통과한 결과만** 보여준다. 무엇을 만들었고, 내부 검토에서
무엇을 고쳤는지 짧게 함께 말한다.

## 경계

- 장 배열을 바꾸지 않는다. 순서 변경은 `deck-plan` 으로 FLOW.md 부터 고친다.
- 대본을 고치지 않는다. 대본이 화면과 어긋나면 말로 알리고 `deck-polish` 로 넘긴다.
- 사용자가 "피드백만" 또는 "확인만" 이라고 하면 파일을 고치지 않고 말로 답한다.
- 이미지가 없으면 만들어내지 않는다. 표지는 패턴 A의 1열 변형을 쓰고, 본문에서 필요한 이미지는 자리표시자를 두고 무엇이 필요한지 말한다.
