# 실패 목록

발표자료를 한 벌 만들면서 **실제로 터진 것들**만 적었다. 예상되는 문제는 넣지 않았다.
`scripts/deck_verify.py`의 검사 항목은 전부 여기서 나왔다.

---

## 0. 측정 방식 자체가 틀렸던 건

**가장 먼저 적는다. 다른 항목을 잘못 판정하게 만드는 메타 실패다.**

넘침을 재려고 `.deck` 에 인라인 스타일로 크기를 강제했다.

```js
deck.style.width = '1366px'; deck.style.height = '768px';   // ← 틀렸다
```

레이아웃 박스는 바뀌지만 `vh` · `dvh` · `clamp(...vh...)` 는 **바깥 창을 계속 따라간다.**
그래서 존재하지 않는 넘침이 계산됐고, "3장이 175px 잘린다"는 잘못된 보고를 했다.
실제로는 원본도 모든 16:9 크기에서 멀쩡했다.

**반드시 실제 크기의 iframe으로 잰다.**

```js
const f = document.createElement('iframe');
f.style.cssText = 'width:1280px;height:720px';
f.src = deckUrl;                       // 독립된 진짜 뷰포트가 생긴다
```

교훈: 측정 도구를 먼저 검증하지 않으면, 없는 버그를 고치고 있는 버그를 놓친다.

## 1. 반응형 `@media` 가 인쇄로 샘

**증상** — 첫 PDF에서 모든 다단 그리드가 1열로 무너지고 글자가 겹침.

**원인** — `@media (max-width:900px)` 에 `screen` 한정이 없었다. 인쇄 시 페이지 박스 폭이
조건에 걸려 모바일 레이아웃이 적용됐다.

**고침** — `@media screen and (max-width:900px)`.
발표 덱이라면 애초에 **반응형 블록을 두지 않는 게 낫다.** 폰으로 볼 일이 없고,
이 블록이 없으면 이 사고 자체가 불가능하다.

**검사** — `print-isolation`

---

## 2. PDF 인쇄 설정 누락

| 빠진 것 | 결과 |
|---|---|
| `@page{size:1280px 720px;margin:0}` | A4 세로에 얹혀 축소·분할 |
| `print-color-adjust:exact` | "배경 그래픽" 체크를 안 하면 배경·보더 색이 전부 빠짐 |
| `.deck{transform:none!important}` | JS가 넣은 인라인 `scale()` 이 인쇄에도 살아남음 |

세 번째는 고정 캔버스로 옮기면서 새로 생긴 함정이다. 인라인 스타일이라
`!important` 없이는 못 이긴다.

**검사** — `print-setup`

## 3. 글자가 뒷줄에서 안 읽힘

**증상** — 발표를 마치고 나서야 "글자가 작았다"는 걸 알았다.

**원인** — 타이포를 `vw` 기준으로 잡았다. `clamp(14px, 1.15vw, 20px)`.
`vw` 는 화면 **너비**를 따르는데, 가독성을 결정하는 건 화면 **높이 대비 글자 비율**이다.
시야각은 해상도와 무관하게 고정이기 때문이다.

1920×1080에서 실측하니 본문이 슬라이드 높이의 **1.9%**, 라벨류는 **1.1%** 였다.
PowerPoint 기본 본문이 3.3%다. 라벨은 표준의 3분의 1이었다.

`clamp` 상한(20px)에 걸려 화면이 커져도 글자가 더 안 커진 게 결정적이었다.

**고침** — 슬라이드 높이 비율로 정하고, 고정 캔버스에서는 절대 px로 굳힌다.

```
h1 72  h2 50  h3 25  lead 24  body 20  label 16     (720 기준 10 / 6.9 / 3.5 / 3.3 / 2.8 / 2.2%)
절대 하한 2.0% = 14.4px
```

**딸린 대가** — 글자를 1.5배 키우면 5열 레이아웃에 기존 텍스트가 안 들어간다.
글자 크기 규칙과 **슬라이드당 글자 예산은 한 몸이다.** 하나만 정할 수 없다.

**검사** — `font-floor`

## 4. 고정 px `min-height` 가 유동 타이포와 싸움

**증상** — 폰트를 키우자 여러 장이 좁은 화면에서 넘쳤다.

**원인** — `.scene{min-height:420px}`, `.sprint-card{min-height:320px}` 등 7곳.
카드 높이는 고정인데 안의 글자는 유동이라, 화면이 줄면 반드시 터진다.

**고침** — `em` 기반 패딩으로 바꾸고 높이는 그리드가 정하게 둔다.

## 5. 장식 요소가 컨테이너 밖에 있었음

**증상** — 표지가 어떤 크기에서도 정확히 14px 넘쳤다. 처음부터 있던 값이다.

**원인** — `.cover-visual-wrap::after{bottom:-14px}`. 레드 장식 바가 컨테이너 밖으로
14px 나가 있었고, 그게 그대로 넘침이 됐다.

**고침** — 부모에 `padding-bottom:14px`, 바는 `bottom:0`. 보이는 모습은 같다.

---

## 6. 폰트 크기를 지정하지 않은 인라인 요소

**증상** — 전체 폰트를 키웠는데 화살표 몇 개만 16px로 남아 있었다.

**원인** — `.flow-steps b`, `.journey b` 에 `font-size` 가 없어 브라우저 기본값(16px)을 썼다.
색만 지정하고 크기를 잊은 경우다.

**교훈** — 타이포 토큰을 바꿀 때는 **모든 리프 요소의 계산된 크기**를 훑어야 한다.
셀렉터 목록만 보면 놓친다.

**검사** — `font-floor` (렌더 검사가 계산된 스타일로 잡는다)

## 7. 같은 배지가 세 가지 뜻으로 쓰임

**증상** — `badge.plan` 이 7장에서 "사람이 담당", 8장에서 "Sprint 1",
9장 범례에서 "도메인 전환안" 이었다. 회색 점 하나에 의미 셋.

**고침** — 상태 배지는 **구현 상태 하나의 축**에만 쓴다.
역할은 `.role-tag`, 단계는 `.phase` 로 분리한다.

**검사** — `badge-semantics`

## 8. 범례와 카드의 색 의미가 반대

**증상** — 범례에서 빨강 = "현재 확인됨", 그리드에서 빨강 = "도메인 전환안".

```css
.service.confirmed{border-color:#888}    /* 회색 */
.service.proposed{border-color:var(--red)}
```

**고침** — 카드 쪽이 옳았다(레드 = 이번 제안이 바꾸는 것). 범례를 카드에 맞췄다.
카드마다 상태 칩도 넣어 범례를 안 봐도 읽히게 했다.

**교훈** — 어느 쪽을 고칠지는 **의미로 정한다.** 레드는 "이번에 새로 만드는 것"에 써야
강조가 정보를 전달한다.

**검사** — `legend`

## 9. 색 별칭이 이중으로 싸움

**증상** — `--teal` 이 실제로는 빨강(`#e32626`)이었다. `--blue`, `--orange`, `--mint` 도 전부.

**원인** — 다른 색 팔레트로 만든 덱을 레드 테마로 바꾸면서, 원래 규칙 아래에
덮어쓰기 블록을 덧붙였다. 토큰 이름과 실제 값이 어긋난 채 두 층이 싸웠다.
"teal 좀 바꿔줘"가 통하지 않는 상태.

**고침** — 두 층을 하나로 합치고 별칭을 전부 제거. 의미 기반 이름만 남겼다.

**전조** — 죽은 셀렉터가 쌓이는 것. 정리 전 미사용 셀렉터가 18개였다.

**검사** — `dead-css`

## 11. 순서를 나중에 바꿔 세 곳을 고침

**증상** — 4·5장을 맞바꾸면서 슬라이드 번호, 푸터 문구, FLOW.md 를 모두 고쳐야 했다.

**원인** — 흐름 검토를 HTML 완성 뒤에 했다.
원래 문제는 **문제 → 결과 → 다시 문제** 로 시간이 역행하는 구성이었는데,
FLOW.md 단계에서 걸렸어야 할 문제다.

**고침** — `deck-plan` 이 FLOW.md 에서 멈추고 사람의 승인을 받는 구조로 만들었다.
페이지 번호는 엔진이 자동으로 채우게 해 이 사고의 비용을 줄였다.

**검사** — `page-numbers`

## 12. 줄바꿈이 만드는 지저분함

폰트를 키운 뒤에야 드러난 것들이다.

| 증상 | 고침 |
|---|---|
| `인증 · 사람·에이전/트` 단어 중간 끊김 | `word-break:keep-all` |
| 칩이 줄바꿈되며 `→` 가 줄 끝에 매달림 | 화살표를 다음 칩의 `::before` 로 이동 |
| 캡션 길이가 달라 프레임이 세로로 어긋남 | `align-items:start` + 화살표를 **너비** 기준 `margin-top` 으로 고정 |

마지막 것은 함정이 하나 더 있다. 절대 위치 요소의 `top:%` 는 **컨테이너 높이** 기준이라
캡션 길이에 따라 흔들린다. `margin-top:%` 는 **너비** 기준이라 안정적이다.

## 정리 — 왜 고정 캔버스로 갔나

3·4·5·6·12번은 전부 **유동 레이아웃이라 생긴 문제**다.
1280×720 고정 캔버스 + `transform: scale()` 로 옮기면서 이 계열이 통째로 사라졌다.

- 줄바꿈이 어디서나 동일 → 해상도별 검사 불필요
- 화면과 PDF가 "비슷한" 게 아니라 **같은 캔버스**
- 넘침 검사가 4회에서 **1회**로

PowerPoint · Keynote · reveal.js 가 전부 이 방식인 데는 이유가 있었다.

## 13. 전체 화면을 그대로 캡처해 넣었다

제품 데모 화면을 통째로 캡처해 슬라이드에 올렸다. 화면에서는 멀쩡했는데 발표
화면에서는 **모든 컴포넌트가 작아져 아무것도 읽히지 않았다.**

원인은 두 겹의 축소다. 원본 화면이 이미 슬라이드 폭으로 줄고, 그 슬라이드가 다시
발표 화면 크기로 줄어든다. 원본에서 14px이던 글자는 슬라이드 위에서 5~6px이 된다.

| 증상 | 처리 |
|---|---|
| 캡처 안의 UI 텍스트가 안 읽힘 | 관심 영역만 잘라 낸다. 전체 화면을 넣지 않는다 |
| 두 곳을 말해야 함 | 두 번 잘라 나란히 둔다. 한 장을 축소하지 않는다 |
| 어디를 보라는 건지 모름 | 핀 번호 + 우측 콜아웃 (패턴 M) |

`font-floor` 검사는 **이미지 안의 글자를 보지 못한다.** 기계 검사 0이어도 안심할 수 없는
유일한 영역이다.
