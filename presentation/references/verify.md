# deck-verify

덱을 **두 층**으로 검사한다. 기계가 잡는 것과 사람 관점이 잡는 것은 다르다.

## 1층 · 기계 검사

```bash
python3 <skill-dir>/scripts/deck_verify.py <deck.html>
```

검사 항목은 전부 실제로 터졌던 사고에서 나왔다 (`references/failure-catalog.md`).

| 검사 | 잡는 것 |
|---|---|
| `overflow` | 내용이 잘리는 슬라이드 (`overflow:hidden` 이라 조용히 잘린다) |
| `font-floor` | 슬라이드 높이의 2% 미만 글자 — 뒷줄에서 안 읽힘 |
| `canvas` | 고정 캔버스가 1280×720에서 벗어남 |
| `print-isolation` | 반응형 `@media` 가 인쇄로 새어 PDF 붕괴 |
| `print-setup` | `@page` · `print-color-adjust` · `transform:none` 누락 |
| `badge-semantics` | 같은 배지가 여러 의미로 쓰임 |
| `legend` | 범례 색과 카드 색 불일치 |
| `asset-path` | HTML·CSS 주석을 제외한 덱 폴더 밖 참조 / 없는 파일 |
| `dead-css` | 사용자가 추가한 미사용 클래스 경고; 스타터 패턴은 `template-css` 정보 한 줄 |
| `foot-position` | 푸터 하단이 캔버스 하단에서 10% 이상 떨어짐 — 경고 |
| `empty-content` | 본문 영역의 위·아래 여유 합계가 본문 높이의 35% 이상(카드 박스 포함) — 정보 |
| `page-numbers` | 번호 하드코딩·불연속 |
| `palette` | `:root`·`[data-theme]` 밖 CSS에 색 값을 직접 씀 — 경고 (테마를 바꿔도 그 자리만 남는다) |
| `dg-edge` | 구조도 선의 `data-from`·`data-to` 가 없는 노드를 가리킴 |
| `dg-overlap` | 구조도 노드끼리 겹침 |
| `dg-numbers` | 그림·코드 번호와 범례·결과 칸 번호가 짝이 안 맞거나, 범례가 1부터 차례가 아님 |
| `code-overflow` | 코드 줄이 상자 오른쪽으로 넘쳐 잘림 (`<pre>`는 줄을 접지 않는다) |
| `code-budget` | 코드 블록 12줄 초과 — 경고 |
| `guide` | 갤러리 견본 안내(`.guide`)가 남아 있음 — 경고 (갤러리 덱 자신은 정보) |
| `text-contrast` | 렌더된 글자색과 그 뒤 배경의 대비가 3:1 미만. 한 장에만 모드·테마를 걸 때 상속이 깨지는 사고를 잡는다 (그라데이션·그림 위 글자는 건너뜀) |
| `dg-label` | 선 라벨이 노드를 가림 — 경고 |
| `dg-budget` | 구조도 하나에 노드 9개 초과 — 경고 |

**검사기는 선이 문장을 가로지르는지는 보지 못한다.** 구조도가 있는 장은 스크린숏이나 PDF로 직접 본다.

**검사기는 이미지 안의 글자를 보지 못한다.** 생성 이미지나 화면 캡처의 글자 크기는
사람이 확인해야 한다.

수치 근거가 있으면 다음도 돌린다.

```bash
python3 <skill-dir>/scripts/deck_numbers.py <deck.html> <results.json> [data.csv ...] --ignore-pages --ignore-years --ignore-times
```

**행 번호·일련번호 열이 있는 CSV를 근거로 주면 정수 검사가 무력해진다. 계산된 결과 파일을 근거로 준다.** 예시 덱은 `results.json` 하나만 사용한다.

슬라이드별 근거에 없는 텍스트 숫자를 보고한다. 소수는 표시 자릿수로 반올림해 대조하며(0.292 → 0.29), 개수 정수는 정확히 맞아야 한다. `%`는 비율 근거도 허용하며 표시 자릿수로 반올림한다. 무시 옵션은 페이지·연도·시간을 제외하고, 추가 비데이터 표기는 `--ignore-regex`로 지정한다. `--ignore-pages`의 슬래시 표기는 `.page` 또는 푸터 안의 독립된 정수 `N / M`만 제외한다. 본문 비율과 소수 비율은 보존한다. 제외된 값이 실제 데이터인지 검토한다. 숫자 값이 근거에 있다는 것만 확인하므로 단위·분모·계산 결과·문맥은 정합성 리뷰에서 판단한다. 이미지·가상 요소·실행 후 삽입된 숫자는 추출하지 못한다. 종료 코드는 통과 0, 근거에 없는 숫자 1, 입력 오류 2다.

의도한 여백이면 `empty-content`은 수정하지 않아도 된다. 푸터 경고는 실제 배치를 확인한다.

오류가 있으면 여기서 먼저 정리한다. 2층은 그 뒤다.

## 2층 · 서브에이전트 리뷰

관점마다 **별도 에이전트**로 돌린다. 한 에이전트에 두 역할을 주면 관점이 섞인다.
전부 돌리지 않는다. **항상 둘 + 조건부**로 고른다.

| 역할 | 언제 | 무엇을 보는가 |
|---|---|---|
| **청중** | 항상 | 그래서 뭐? 가 나오는 지점, 전달 순서, 시간 배분 |
| **UI/UX** | 항상 | 3초 판독, 시선 이동, 강조 분산, 정렬·여백 |
| 산출물 정합성 | FLOW 에 `산출물 분담` 이 있을 때 | 덱의 주장이 산출물에도 실려 있는가 |
| 기술 정합성 | 설계·명세가 발표 주제일 때 | 덱의 도식이 실제 설계와 어긋나지 않는가 |
| 스토리·카피 | 설득이 목적인 발표일 때 | 문구가 주장을 약하게 만들고 있지 않은가 |

역할을 늘릴수록 지적은 늘지만 대부분 서로 겹친다. 셋을 넘기지 않는다.

### 청중 리뷰

`FLOW.md` 의 청중 설정을 주고, **그 사람인 척** 보게 한다.

- 어느 장에서 "그래서 뭐?" 가 나오는가
- 청중이 결과·화면을 처음 보기까지 몇 초가 걸리는가
- 어느 장에서 질문하고 싶어지는가. 그 질문에 덱이 답하는가
- 근거 없이 단정하는 주장이 있는가
- `제안`을 `확인됨`으로 오해할 곳이 있는가
- 마지막에 무엇을 결정해야 하는지 분명한가

**산출물은 반드시 시간 재배분표로 받는다.** 산문 지적은 읽히고 끝나지만 표는 결정을 만든다.

| 장 | 현재 | 제안 | 이유 |
|---|---:|---:|---|
| 3 원문 변경 | 30 | **40** | 차별점의 출발점. 여기서 제대로 아프게 |
| 4 수집 트리거 | 35 | **15** | 청중 관심 최저. 한 문장으로 |

합계가 목표 시간을 넘는지도 함께 적게 한다.

### UI/UX 리뷰

덱을 PDF로 뽑아 실제로 보게 한 뒤 묻는다. 이 리뷰용 PDF는 별도 PDF 요청 없이 verify 단계에서 만들어도 된다. [export.md](export.md)의 규칙대로 기존 PDF를 덮어쓰지 않고 `presentation.pdf`, `presentation_v2.pdf`처럼 번호를 올린다.

- 3초 안에 각 장의 결론이 잡히는가
- 시선이 몇 번 꺾이는가. 읽는 순서가 자연스러운가
- 강조(클레이)가 한 장에 여러 곳이면 강조가 아니다
- 균등 나열이 우선순위를 지우고 있지 않은가
- 캡처·생성 이미지 안의 글자가 읽히는가
- 정렬·여백·색 대비에 눈에 걸리는 곳

## 3층 · 확인 후 수정

**리뷰 결과를 바로 반영하지 않는다.** 사용자에게 이렇게 전한다.

```
[UI/UX] 5장에서 클레이 강조가 3곳이라 시선이 분산된다는 지적입니다.
        → 1순위 카드만 남기고 나머지 둘을 회색으로 내릴까요?

[청중]  7장을 4장 자리로 올리라는 지적입니다. 결과 화면을 보기까지 2분 40초가 걸립니다.
        → 순서를 바꾸면 FLOW·SCRIPT도 같이 고쳐야 합니다. 진행할까요?
```

지적마다 **무엇을 어떻게 고칠지 제안하고, 사용자의 답을 받은 뒤에** 고친다.
사용자가 고르지 않은 지적은 건드리지 않는다.

장 순서·주장이 바뀌는 지적은 덱만 고치고 끝내지 않는다. `deck-plan` 으로 FLOW 를,
`deck-narrate` 로 SCRIPT 를 같이 고친다. 세 파일이 어긋나면 다음 수정에서 반드시 사고가 난다.

수정한 뒤 1층 기계 검사를 다시 돌려 오류 0을 확인한다.

## 외부 피드백 심사

사용자가 다른 사람이나 다른 모델에게 받은 피드백을 붙여넣고 "어떻게 생각해?" 라고
물으면, 통째로 수용하지도 반박하지도 않는다. **항목으로 쪼개 판정한다.**

```
1. "액터 표를 넣어야 한다"        → 반려. 산출물이 맡기로 한 주제다 (FLOW 산출물 분담)
2. "결과 화면이 너무 늦다"        → 채택. 결과 지연 점검에 걸린다
3. "시간이 30초 초과한다"         → 조건부. 4장을 15초로 줄이면 해소된다
```

- **채택 / 조건부 / 반려** 셋 중 하나로 판정하고, 근거를 FLOW·SCRIPT·검사 결과에서 댄다
- 피드백이 선 전제가 틀렸으면 그것부터 말한다. 평가 대상이 덱이 아니라 산출물이면
  시간 배분 지적의 절반은 무효가 된다
- 판정만 하고 멈춘다. 무엇을 반영할지는 사용자가 고른다

## 경계

- 서브에이전트는 이 스킬이 호출될 때만 띄운다.
- 리뷰는 읽기 전용이다. 사용자가 고르기 전에는 덱 파일을 바꾸지 않는다.
- 지적이 없으면 없다고 말한다. 억지로 만들어내지 않는다.
