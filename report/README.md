# report

분석 · 과제 · 프로젝트 결과를 **한 쪽 = 한 메시지**인 A4 page-fixed HTML 보고서와 PDF로 만든다.

**예시:** [간식 서랍은 오후 3시 전에 비는가](https://zaehorang.github.io/horang-skills/report/examples/snack-drawer/report.html) — 시드 고정 가상 데이터로 만든 6쪽 보고서. 같은 분석의 발표 덱이 [`presentation`](../presentation) 예시에 있다.

## 왜 만들었나

보고서가 쪽 중간에서 끊기고, 마지막 줄에 단어 하나만 남고, 제목을 읽어도 결론이 안 보였다. 독자가 각 쪽의 제목과 숫자만 훑어도 결론을 알 수 있어야 하는데, 그러려면 쪽을 먼저 계획하고 넘침과 줄바꿈을 기계로 잡아야 한다.

## 무엇을 해주나

- 쪽마다 "결론형 제목 한 문장 + 들어갈 그림 · 표"를 먼저 정하고 쓴다. "실험 2" 대신 "피처를 줄일수록 점수가 올랐다".
- 미색 종이 · 명조 제목 · 강조색 하나의 편집물 디자인 템플릿. CSS를 새로 짜지 않고 컴포넌트만 조합한다.
- `scripts/report_tool.py check`가 쪽 넘침 · 짧은 꼬리 줄 · 줄바꿈 지점을 검사한다. 넘침 0건, 꼬리 줄 0건이 될 때까지 고친다.
- 그림은 보고서와 같은 톤의 matplotlib 스타일로 다시 그린다. 덱으로 이어질 보고서면 제목 없는 판본을 따로 저장한다.
- 요청하면 쪽별 발표 대본을 별도 Markdown으로 뽑는다.

산출물은 `report.html` + PDF (+ 쪽별 대본 `.md`).

## 설계에서 정한 것

- **page-fixed.** 흐르는 문서는 어디서 끊길지 모른다. A4 쪽을 단위로 잡아야 "한 쪽 = 한 메시지"가 지켜지고 PDF와 화면이 같다.
- **제목은 결론이다.** 주제를 적은 제목은 읽어도 아는 게 없다.
- **수치는 실행 로그에서 직접 읽는다.** 기억이나 앞선 대화의 숫자를 쓰지 않고, 마지막에 PDF에서 숫자를 뽑아 로그와 대조한다.
- **그림 스크립트는 스타일을 복사해 넣는다.** 스킬 폴더를 import하면 다른 곳에서 재현되지 않는다.
- **대본은 보고서에 넣지 않는다.** 보고서에는 분석과 결과만 둔다. 슬라이드를 따로 띄워 말해야 하면 [`presentation`](../presentation)을 쓴다. 읽히는 문서와 들리는 말은 다른 산출물이다.
