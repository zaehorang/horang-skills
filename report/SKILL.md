# report

보고서는 **한 쪽 = 한 메시지**로 만든다. 독자가 각 쪽의 제목과 숫자만 훑어도 결론을 알 수 있어야 한다.

`<skill-dir>`은 이 `SKILL.md`가 있는 폴더다. 디자인과 줄바꿈 규칙은 [DESIGN.md](DESIGN.md)에 있다. 새 보고서를 만들거나 디자인을 바꿀 때는 끝까지 읽는다.

## 준비물

| 파일 | 용도 |
|---|---|
| `assets/report_template.html` | 시작 템플릿. 표지 · 요약 · 본문 · 재현 쪽 예시와 전체 CSS |
| `assets/mpl_style.py` | 보고서와 같은 톤의 그림 색 · 스타일 |
| `scripts/report_tool.py` | `check`: 쪽 넘침 · 짧은 꼬리 줄 · 줄바꿈 지점 검사. `render`: PDF와 쪽별 PNG 미리보기 |
| `examples/snack-drawer/` | 완성 예시. 시드 고정 가상 데이터로 만든 6쪽 보고서와 그 분석 코드 · 그림 · PDF |

`report_tool.py`는 표준 라이브러리만 쓰고, 헤드리스로 실행할 수 있는 Chromium 계열 브라우저가 필요하다. PNG 미리보기에는 PDF를 이미지로 바꾸는 명령줄 도구가 필요하다. 없으면 PDF를 직접 열어 본다.

## 순서

1. **근거 확인.** 보고서에 넣을 수치는 실행 로그나 결과 파일에서 직접 읽는다. 기억이나 앞선 대화의 숫자를 쓰지 않는다. 제출 요건(파일명, 형식, 분량, 금지 사항)도 먼저 확인한다.
2. **원본 백업.** 기존 보고서를 다시 디자인한다면 원본 HTML을 임시 폴더에 복사해 둔다.
3. **쪽 계획.** 쓰기 전에 쪽마다 "결론형 제목 한 문장 + 들어갈 그림·표"를 표로 정한다. 기본 흐름은 다음과 같다.

   ```
   표지 → 한눈에 보는 결과 → 문제와 데이터 → 검증 설계(규칙 준수 근거가 중요하면 별도 쪽)
        → 구성 요소별 접근 → 최종 결과 → 기각한 선택과 한계 → 재현 방법 → 부록
   ```
4. **그림.** 그림 스크립트에 `assets/mpl_style.py`의 rcParams와 색 상수를 **복사**해 넣고 다시 그린다. 결과물 코드가 스킬 폴더를 import하면 다른 곳에서 재현되지 않는다. 저장한 이미지를 직접 열어 범례 · 라벨 겹침을 확인한다.
5. **HTML 작성.** 템플릿을 보고서 위치에 복사하고 컴포넌트만 조합한다. CSS를 새로 짜지 않는다. 문장은 짧게, 나열은 표로 쓴다. 긴 설명은 독자가 꼭 납득해야 하는 곳(규칙 준수 근거, 핵심 설계 이유)에만 설명 상자로 둔다.
6. **검사 루프.** 넘침 0건, 짧은 꼬리 줄 0건이 될 때까지 고친다. 그다음 줄바꿈 지점 목록을 끝까지 읽고 갈라진 단어 묶음을 묶거나 문장을 다시 쓴다(DESIGN.md 5절).

   ```bash
   python3 <skill-dir>/scripts/report_tool.py check <report.html> --breaks
   ```
7. **렌더와 눈 검토.** PDF와 쪽별 PNG를 만들고 모든 쪽을 이미지로 본다. 표지, 숫자 열 정렬, 그림 겹침, 여백 균형을 확인한다.

   ```bash
   python3 <skill-dir>/scripts/report_tool.py render <report.html> --png <임시 폴더>/pages
   ```
8. **수치 대조.** PDF에서 텍스트를 뽑아 핵심 숫자를 실행 로그와 대조한다.
9. **사본 동기화.** 제출 폴더나 코드 압축본에 보고서가 들어간다면 같은 PDF로 다시 맞추고 바이트가 같은지 확인한다.

## 내용 원칙

- 쪽 제목은 주제가 아니라 결론이다. "실험 2" 대신 "피처를 줄일수록 점수가 올랐다".
- 보고서에는 분석과 결과만 둔다. 발표 진행 문구, 순위표, 작업 과정의 잡담은 사용자가 원하지 않는 한 넣지 않는다.
- 최종안이 아닌 대안이나 규칙 위반 소지가 있는 방법을 어디까지 남길지는 사용자가 정한다. 정해지면 보고서 전체를 그 기준으로 맞춘다.
- 한계와 가정은 숨기지 않고 표로 짧게 쓴다.
- 숫자는 표와 숫자 카드에 두고, 문장에는 결론에 필요한 숫자만 쓴다.

## 발표 대본 (요청 시)

대본은 보고서에 넣지 않고 별도 Markdown으로 둔다. 보고서 화면을 넘기며 말하는 짧은 발표용이다. 슬라이드를 따로 만들어야 하면 같은 묶음의 `presentation` 스킬을 쓴다.

1. 맨 위에 `시간 | 보고서 쪽 | 말할 내용` 표를 둔다. 발표에서 건너뛸 쪽도 적는다.
2. 쪽마다 절을 만들고 "가리킬 곳"(그림 · 표 이름)과 말할 문장을 적는다.
3. 맨 아래에 `질문 | 답 | 열 페이지` 표를 둔다.

보고서의 쪽 번호나 그림 번호가 바뀌면 대본도 함께 고친다.

## 경계

- 요청받은 보고서만 고친다. 데이터 · 모델 · 제출 파일은 바꾸지 않는다.
- 그림 스크립트는 스타일만 바꾸고, 다시 그린 뒤 그림의 수치가 그대로인지 확인한다.
